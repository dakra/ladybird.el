#+TITLE: ladybird — Ladybird pages in an Emacs canvas

=ladybird= shows web pages rendered by the [[https://ladybird.org][Ladybird]] browser in an Emacs buffer.  A Ladybird
server process renders the page and sends the changed pixels; a native module paints
them into an Emacs 32 canvas image; the mouse, the wheel and the keyboard go back to the
page.  The server can run on this machine or on another one, and with a socket its pages
outlive the Emacs that shows them.

=ladybird= is a working name.

* Status

The Emacs side is in this repository: the Lisp package, the native module, a mock server
and the tests.

The Ladybird side, a headless mode =Ladybird --headless=emacs= that speaks the protocol
of [[file:plans/01-protocol.md][plans/01-protocol.md]], is under development on a branch of Ladybird named
=emacs-headless= and is in no Ladybird release.

The two are run together by the live test matrix (see Testing): a macOS server on this
machine over standard input and output and over a Unix socket, with frames in shared
memory, and a Linux server in a virtual machine over ssh and over an ssh-forwarded
socket, with frames in the stream.  The matrix runs at a device pixel ratio of 1; a
ratio of 2 is checked by hand on a Retina display.  Not tested: TCP, Emacs on Linux and
a server on a machine across a real network.

=tools/mock-server.py= stands in for the server in the tests: it draws a test gradient,
marks mouse presses and typed keys, draws hint labels, and answers the protocol's
commands with canned data.

A server holds several pages, each in its own buffer (see Several pages): 16 by
default, or as many as =--emacs-max-views=N= says.  The live matrix tries them on the
macOS server on this machine and the Linux server in the virtual machine, over all four
connections (=live-pages=): two pages painting their own canvases, a cookie one sets and
the other reads, a page in no window sending no frames and a full frame once it is shown
again, where =ladybird-new-page-display= puts a new page, the limit, closing a page that
is animating, and the pages a socket server kept coming back with =ladybird-connect=.  A
server whose welcome names no number, or the number 1, holds one page: a command that
opens a second page on it loads the URL in the page there is and says so.

A page can open pages of its own (=window.open=, a link with a =target=, a middle click),
which get buffers in the background (see Several pages).  The live matrix tries them on
both servers over all four connections (=live-popups=): a link with =target=_blank=,
=window.open= with =window.opener=, a page closing its window or itself, the limit giving
a blocked popup, and a hinted click.

Not there yet: view source, uploads from this machine (the file picker returns paths on
the server's machine), downloads, bookmarks and profiles.

* Requirements

- Emacs 32 with canvas images and dynamic modules.
- The native module, built with Zig 0.17 (=make build=).
- A server: Ladybird built from its =emacs-headless= branch, or the mock server, which
  needs Python 3.11 or later.

* Building

#+begin_src sh
make build      # ladybird-module.dylib or .so next to the Makefile
make test       # Zig tests, module tests in Emacs, ERT tests of the package
#+end_src

Put =lisp/= on the =load-path=.  The module is looked for next to the Lisp files and in
the directory above them; =ladybird-module-directory= names another place.

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/ladybird/lisp")
(require 'ladybird)
#+end_src

* Quick start

With a Ladybird that has the headless mode:

#+begin_src emacs-lisp
(setq ladybird-program "/path/to/Ladybird")
;; M-x ladybird RET https://ladybird.org RET
#+end_src

With the mock server:

#+begin_src emacs-lisp
(setq ladybird-hosts
      '(("mock" :command ("python3" "-I" "/path/to/ladybird/tools/mock-server.py")))
      ladybird-default-host "mock")
;; M-x ladybird RET mock://start RET
#+end_src

To open links from other packages in ladybird:

#+begin_src emacs-lisp
(setq browse-url-browser-function #'ladybird-browse-url)
;; or only some of them
(add-to-list 'browse-url-handlers '("\\`https?://.*\\.internal/" . ladybird-browse-url))
#+end_src

=ladybird-browse-url= loads the URL in the page buffer used last, and opens a new one when
there is none.

=C-u C-c C-l= opens a URL in a new page buffer on the same server, and =C-c C-s= switches
between page buffers by title and URL.

* Hosts and transports

=ladybird= starts =ladybird-program= as =PROGRAM --headless=emacs= and talks to it over its
standard input and output.  Other servers are named in =ladybird-hosts=, an alist of a
label and one or more endpoints, tried in order:

| Endpoint                               | Connection                                     |
|----------------------------------------+------------------------------------------------|
| ="local"=                              | =ladybird-program= as a local process            |
| ="ssh:HOST"=, ="ssh://USER@HOST:PORT"= | =ladybird-program= on HOST, run by =ssh -T=      |
| ="/PATH"=, ="unix:///PATH"=            | a Unix socket                                  |
| ="tcp://HOST:PORT"=                    | a TCP port, unauthenticated                    |
| ="tls://HOST:PORT"=                    | a TCP port with TLS                            |
| =(:ssh HOST :program P :args LIST)=    | ssh with another program or arguments          |
| =(:command (PROGRAM ARG...))=          | that command as a local process                |
| =(:kind unix :path PATH :shm nil)=     | a Unix socket, without shared memory           |

#+begin_src emacs-lisp
(setq ladybird-hosts '(("devbox" . "ssh://devbox")
                     ("work" "/tmp/work.sock" "tcp://work.tailnet.example:7070")))
#+end_src

=M-x ladybird= opens on =ladybird-default-host=: the local server, a label, or =ask=.  With a
prefix argument it asks.  =M-x ladybird-connect= connects without opening a page, gives
every page the server has open a buffer and shows one of them: the page buffer used last
if it is one, else the first; the echo area says how many there are.

A server on standard input and output lives as long as its connection, so its pages end
with Emacs or with the ssh session.  A server that listens on a socket keeps its pages:
kill the buffers with =ladybird-keep-view-on-kill= set, or quit Emacs, and the next
connection shows them again.  It also keeps running once its last page is closed, which
the echo area says; it stops when it is stopped where it runs, for example with =C-c= in
its terminal or by ending its process.  To reach such a server on another machine, forward its
socket:

#+begin_src sh
# on devbox
Ladybird --headless=emacs --emacs-socket=/run/user/1000/ladybird.sock
# here
ssh -N -o StreamLocalBindUnlink=yes -L /tmp/devbox.sock:/run/user/1000/ladybird.sock devbox
#+end_src

#+begin_src emacs-lisp
(setq ladybird-hosts '(("devbox" . "/tmp/devbox.sock")))
;; or, saying that the socket is forwarded:
(setq ladybird-hosts '(("devbox" :kind unix :path "/tmp/devbox.sock" :shm nil)))
#+end_src

With =ControlMaster auto= in =~/.ssh/config=, =ssh -N -L= hands the forwarding to the
shared connection and returns at once.  Either give the forwarding a connection of its
own with =-o ControlMaster=no -o ControlPath=none=, or end it with =ssh -O exit devbox=.

Local servers hand frames over in shared memory, one segment per page.  Over a forwarded
socket the segment cannot be opened here; the server is told and sends the pixels in the
stream, compressed with zstd.  That costs the first frame of the first connection; the
endpoint is remembered for the rest of the Emacs session and not offered shared memory
again.  =:shm nil= in the endpoint says it up front.  The module maps a segment at the size it has then and
trusts the server not to shrink it: reading from pages that are gone would kill Emacs.
Only a server on this machine can hand over a segment, and one run by the same user can
harm Emacs in other ways already; for a Unix socket of a server that is not, say so with
=:shm nil= in its endpoint.

A server reached through a Unix socket counts as being on this machine when its endpoint
does not say =:shm nil=, its segments could be mapped and it names this machine as its
host.  For any other server, file names are asked for as paths on the server's machine.

A connection that is lost is dialled again after 1, 2, 4 and up to 30 seconds while it
has page buffers (=ladybird-reconnect=); the header line says so.  The buffers keep their
last frame and re-attach to their pages; a page the server no longer has is opened again
with its URL, and so is every page when another server process answers.  A page whose
buffer was killed meanwhile is closed once the connection is back.  The delays start at
one second again after a connection has lasted ten seconds.  A local or ssh server that exited by itself is reported with its exit
status and started again only with =ladybird-reconnect= set to =always=.  When another
client takes the server over the buffers show =[detached]=, and =M-x ladybird-reconnect=
takes it back.

A server is pinged after =ladybird-keepalive-interval= seconds of silence and its
connection dropped when no answer comes within =ladybird-ping-timeout=.

When a local or ssh server cannot be started or exits, the message has the last line it
or ssh wrote to standard error; the buffer =" *ladybird-stderr*"= has all of it.

* Several pages

Every page is a buffer of its own.  =M-x ladybird=, =C-u C-c C-l=, =c= in command mode,
=C-u C-c C-o= on a link, "Open Link in New Buffer" and =ladybird-open-blocked-popup= open a
new page on the server of the current one (=M-x ladybird= on =ladybird-default-host=), with
a view of its own on that server; the pages of a server share its cookies and storage.
=ladybird-new-page-display= says where the new buffer appears: in the selected window
(the default), in another window, or nowhere (=background=).  The buffer goes through
=display-buffer=, so a rule of =display-buffer-alist= for =*ladybird:= buffers comes first.

A server holds as many pages as its welcome's =max_views=: the Ladybird server 16, or N
with =--emacs-max-views=N= (=ladybird-program-arguments= for a server the package starts).
Once it has that many, a further page is refused with a message saying so, before the
server is asked; the message counts the pages that buffers killed with
=ladybird-keep-view-on-kill= left on the server.  =C-c C-s= and =M-x ladybird-connect= give
those pages buffers again, with their current titles and URLs.  A server whose welcome
names no number, or the number 1, holds one page, and a further page loads the URL in it.

A page that a page opens, after a click or key of the user in it, gets a buffer of its
own on the same server, and the echo area names the page that opened it and says that
=C-c C-s= gets there.  It appears in no window, so a page that opens one on every click
takes no window and no focus; it is told it is hidden and renders nothing until a window
shows it.  =C-c C-s= annotates it with the page that opened it.  A page that closes its
window takes its buffer along: a window made for it is deleted and any other shows the
buffer it showed before (=quit-restore-window=); the selected window stays selected.  The buffer goes through =display-buffer= with the
category =ladybird-popup=, so a rule of =display-buffer-alist= can show it, without
selecting its window:

#+begin_src emacs-lisp
(add-to-list 'display-buffer-alist
             '((category . ladybird-popup) (display-buffer-pop-up-window)))
#+end_src

When the server makes no view for the page, the echo area says the popup was blocked and
what =ladybird-open-blocked-popup= does with its URL: open it as a new page, load it in the
page there is on a server that holds one page, or nothing while a server holds all the
pages it can.

A page in no window is told it is hidden, and its server sends it no frames until a
window shows it again; then it repaints in full.  Iconifying a frame or showing it
again counts as hiding or showing its pages.  After a reconnect the pages that were
shown before send a whole frame at once, the others when a window shows them; every page
is told whether a window shows it as soon as the reconnecting command has shown its
page.  =C-c C-s=
(=ladybird-switch-to-page=) reads a page by any part of its title or URL, from every
server; with several servers each is annotated with its host.

There is no tab strip of its own.  Emacs's tab-line shows the page buffers of a window as
tabs:

#+begin_src emacs-lisp
(add-hook 'ladybird-mode-hook #'tab-line-mode)
(setq tab-line-tabs-function #'tab-line-tabs-mode-buffers)
#+end_src

With tab-bar, one tab per page: a page shown in a tab already selects that tab, any
other gets a new one.

#+begin_src emacs-lisp
(add-to-list 'display-buffer-alist
             '("\\`\\*ladybird: " (display-buffer-in-tab)
               (reusable-frames . t)))
#+end_src

That rule also takes the pages that pages open, and selects their tabs.  A rule for
their category that comes first keeps them in the background:

#+begin_src emacs-lisp
(add-to-list 'display-buffer-alist
             '((category . ladybird-popup) (display-buffer-no-window)
               (allow-no-window . t)))
#+end_src

* Keys

A new page buffer starts in =ladybird-command-mode=, where single keys are commands
(below): =n= and =p= scroll, =g= opens a URL, =o= follows a link.  =i= switches to page
mode, and so does a text field of the page that gets the focus, whether by a click, =TAB=,
=o=, a script or autofocus; command mode comes back when no field has the focus.
Command mode switched on by hand while a field has the focus stays; page mode switched on
there also ends when no field has the focus.  =ladybird-initial-mode= set to =page=
starts buffers in page mode instead.

The switching is done by =ladybird-follow-field-focus=, the default of the hook
=ladybird-field-focus-functions=.  Each function in it is called with FOCUSED and
ACTIVATION when the focus moves into or out of the page's text fields.  ACTIVATION is nil
for a focus the page moved without user input, such as autofocus, and also when a key
moves the focus into a frame of another site; such a field calls the functions again with
ACTIVATION when the user first clicks or types in the page.  To stay in command mode until
a click in the field or =i=:

#+begin_src emacs-lisp
(defun my-ladybird-field-focus (focused activation)
  (when (or activation (not focused))
    (ladybird-follow-field-focus focused)))
(setopt ladybird-field-focus-functions '(my-ladybird-field-focus))
#+end_src

In page mode keys go to the page, as in a terminal emulator: what inserts itself, =RET=,
=TAB=, =DEL=, =S-SPC=, the cursor and function keys with any modifiers, and =<escape>= in a
graphical frame.  The Emacs editing and motion keys of =ladybird-translated-keys= are
translated to what does the same in a browser on the server's platform (table below).  The
mouse and the wheel always act on the page.  Everything else keeps its Emacs meaning, in particular
=C-x=, =C-c=, =C-h=, =M-x=, =M-:=, =C-u= and =C-g=, and the keys of =ladybird-emacs-keys=:
=<f1>= (help), =<f3>= and =<f4>= (keyboard macros), =<f10>= (the menu bar) and =<f11>=
(full screen).  A key in that option stays with Emacs also when it is in
=ladybird-translated-keys=.  A numeric prefix argument repeats a key (=C-u 3 a= types
three), and a keyboard macro recorded with =<f3>= and =<f4>= replays its keys into the
page.  With an input method the characters it produces are sent.

With evil or meow the keymaps of their states take keys before =ladybird-mode= sees them;
for keys to go to the page, start page buffers in Emacs state, for example with
=(evil-set-initial-state 'ladybird-mode 'emacs)=.

The package's commands are under =C-c=:

|--------------------------------+---------------------------------------------------|
| =C-c C-l=                      | open a URL; with =C-u= in a new buffer            |
| =C-c C-o=                      | activate a link, button or field by its label     |
| =C-c C-b=, =C-c C-f=           | back, forward                                     |
| =C-c C-r=                      | reload; with =C-u= without the cache              |
| =C-c C-k=                      | stop loading                                      |
| =C-c C-s=                      | switch to another page by its title or URL        |
| =C-c C-w=                      | copy the page's URL                               |
| =C-c C-t=                      | page console output on or off                     |
| =C-c C-n=, =C-c C-p=           | focus the next, the previous link or field (=TAB=, =S-TAB=) |
| =C-c C-q=, =C-q=               | send the next key to the page as it is            |
| =C-c C-y=, =C-y=               | paste the latest kill into the page               |
| =M-w=                          | copy the page's selection                         |
| =C-x h=                        | select all                                        |
| =C-s=, =C-r=                   | find in page                                      |
| =M-s n=, =M-s p=               | next, previous match                              |
| =C-x C-+=, =C-x C-==, =C-x C--=, =C-x C-0= | zoom in, in, out, reset; then =+=, =-=, =0= go on |
| =C-c C-e=                      | =ladybird-command-mode=                             |
| =C-c C-j=                      | back to page mode                                 |

Killing the buffer closes the page.  =C-c C-q= or =C-q= reads one key and sends it
untranslated, so that =C-x=, =C-c=, =C-g= or =C-s= reach the page; in a terminal =ESC=
with a key right behind it is that key with Meta.  A mouse or wheel event after =C-c C-q=
is handled as usual.

In =ladybird-command-mode= (=C-c C-e=) the =C-c= commands, the mouse and the wheel work as
in page mode, and =i=, =RET= or =C-c C-j= send keys to the page again.  The mode line
shows =:Page= or =:Command=; a click on it switches.

| Key in command mode            | Command                                         |
|--------------------------------+-------------------------------------------------|
| =g=                            | =ladybird-goto-url=                               |
| =r=, =R=                       | reload, reload without the cache                |
| =k=                            | stop loading                                    |
| =s=                            | switch to another page by its title or URL      |
| =b=, =f=                       | back, forward                                   |
| =n=, =p=, =<down>=, =<up>=, =C-n=, =C-p= | scroll by =ladybird-scroll-step=        |
| =<left>=, =<right>=, =C-b=, =C-f= | scroll sideways                              |
| =SPC=, =<next>=, =C-v=         | scroll a page down                              |
| =DEL=, =S-SPC=, =<prior>=, =M-v= | scroll a page up                              |
| =<=, =>=, =M-<=, =M->=         | top, bottom                                     |
| =+=, ===, =-=, =0=             | zoom in, in, out, reset                         |
| =o=                            | =ladybird-follow-hint=                            |
| =w=                            | copy the page's URL                             |
| =c=                            | the same URL in a new buffer                    |
| =S=                            | screenshot, saved on the server's machine       |
| =q=                            | bury the buffer; the page stays open            |
| =Q=                            | close the page and kill the buffer              |
| =i=, =RET=                     | back to page mode                               |

Another key that inserts itself says how to get back to the page.

The keys of =ladybird-translated-keys= do in the page what they do in Emacs.  A browser
has other keys for that, and those differ between platforms, so each is translated for
the platform the server runs on:

| Key                                    | In a text field          | Without a focused field | Sent to a macOS server    | Sent to another server    |
|----------------------------------------+--------------------------+-------------------------+---------------------------+---------------------------|
| =C-a=, =C-e=                           | start, end of the line   | top, bottom             | Home, End                 | Home, End                 |
| =C-d=                                  | delete a character       |                         | Delete                    | Delete                    |
| =C-k=                                  | delete to the line's end | bottom                  | Shift+End, Delete         | Shift+End, Delete         |
| =M-b=, =M-f=                           | a word left, right       |                         | Alt+Left, Alt+Right       | Ctrl+Left, Ctrl+Right     |
| =M-d=                                  | delete a word forward    |                         | Alt+Delete                | Ctrl+Delete               |
| =M-DEL=, =M-<backspace>=, =C-<backspace>= | delete a word backward |                       | Alt+Backspace             | Ctrl+Backspace            |
| =C-z=, =C-/=, =C-_=                    | undo                     |                         | the page's undo           | the page's undo           |
| =C-?=                                  | redo                     |                         | the page's redo           | the page's redo           |
| =C-n=, =C-p=                           | next, previous line      | scroll down, up         | Down, Up                  | Down, Up                  |
| =C-f=, =C-b=                           | a character right, left  | scroll right, left      | Right, Left               | Right, Left               |
| =C-v=, =M-v=                           | scroll the page          | a page down, up         | PageDown, PageUp          | PageDown, PageUp          |
| =M-<=, =M->=                           | start, end of the field  | top, bottom             | Command+Up, Command+Down  | Ctrl+Home, Ctrl+End       |

At the end of a line =C-k= removes the line break.  =C-M-_= and =C-S-z= (redo) are
translated too once they are added to the option; other keys added to it are sent as
they are.  A key taken out of it keeps its Emacs meaning.  Both columns were tried
against Ladybird servers on macOS and on Linux.

=C-s= reads the search string in the minibuffer.  The page shows the matches while the
string is typed and the minibuffer shows their number; =C-s= and =C-r= move to the next
and the previous match, =RET= leaves the matches highlighted, =C-g= ends the search.
Ladybird turns the match the search ended on into the page's selection.

=C-c C-o= (=o= in command mode) follows a link from the keyboard.  The page puts a label
made of the characters of =ladybird-hint-alphabet= on every link, button and field in the
window, and typing a label activates its element: a link or a button is clicked, a field
gets the focus and command mode is left, so that typing goes into it.  Each character
narrows the labels the page shows; the echo area shows what has been typed, how many
labels are left and, for the last one, its text or URL.  A character that continues no
label is refused with a beep, =DEL= takes the last one back, and =C-g= or =<escape>= (in
a graphical frame; in a terminal =ESC= starts a Meta key) ends without a choice.  Any
other key, a click or the wheel ends the hints too and then does what it does otherwise;
moving the mouse does not.  With =C-u C-c C-o= a link opens in a new buffer, if it is an
http or https URL, or a file URL on a page that is a file itself; another one is refused
with a message.  Characters typed before the labels arrive count.  When the page ends the
hints (it navigates, crashes or does not answer in time) or the server refuses them, they
end here too, with a message.  It needs a server whose welcome lists the =hints= feature.

What a page asks comes to the minibuffer: alerts (in the echo area; =ladybird-alert-style=
makes them wait for a key), confirmations, prompts, the choices of a select element,
files, colours, dates, permissions and URLs for other programs.  =C-g= declines, and so
does any other way out of the prompt.  While the minibuffer is in use a question waits
for it.  A question the server withdraws closes by itself.

A permission and a URL for another program are answered with a word typed or completed in
full (=allow once=, =allow always=, =deny=; =open on server=, =open here=, =deny=), and
keys typed before the question appeared are discarded.  =RET= on a part of a choice, or on
any other text, asks again with the input gone, so keys meant for the page do not answer
it; =RET= on nothing declines.  =open here= hands the URL to
=browse-url-secondary-browser-function= and is offered for http, https and mailto URLs
only.

A right click pops up a menu for the link, image, selection or text field under the
pointer.  Its "Open Link" and "Open Link in New Buffer" load the same URLs as
=C-u C-c C-o=.

The header line shows the page's URL first, at least its scheme and host, then the
title in the room that is left.

* Display resolution

=ladybird-device-pixel-ratio= is the number of device pixels the server renders per Emacs
pixel.

On macOS it is 1.0 by default: the page is rendered at one pixel per point and Emacs
scales the canvas up on a Retina display, so text is less sharp than in the rest of the
frame.  The NS port of Emacs draws a canvas without its image transform (=:scale=), so a
page rendered at the display's resolution would show only its top left part.

With =ladybird-device-pixel-ratio= set to nil the ratio is the frame's scale factor
(=frame-scale-factor=) and the canvas is shown scaled down by it, one canvas pixel per
device pixel.  On macOS that needs an Emacs built with
=plans/emacs-canvas-ns-transform.patch=, which makes the NS port keep the transform.
For Homebrew's emacs-plus the patch is registered in =~/.config/emacs-plus/build.yml=
under the name =canvas-ns-transform=.

Elsewhere the default is nil.

| =ladybird-emacs-keys=               | =<f1>= =<f3>= =<f4>= =<f10>= =<f11>= | keys that keep their Emacs meaning |
| =ladybird-initial-mode=             | =command=          | =command= or =page=: where a new buffer's keys go |
| =ladybird-field-focus-functions=    | see above          | called when a text field gets or loses the focus  |
| =ladybird-keep-view-on-kill=        | nil                | leave the page open when its buffer is killed     |
| =ladybird-new-page-display=         | =selected-window=  | where a page a command opens appears: =selected-window=, =other-window=, =background= |
| =ladybird-hint-alphabet=            | ="asdfghjkl"=      | characters of the labels of =C-c C-o=; 2 to 36 of a-z and 0-9 |
| =ladybird-reconnect=                | t                  | nil, t or =always=                                |
| =ladybird-keepalive-interval=       | 30                 | idle seconds before a ping                        |
| =ladybird-ping-timeout=             | 10                 | seconds to wait for its answer                    |
| =ladybird-connect-timeout=          | 10                 | seconds to wait for a connection and its welcome  |
| =ladybird-console-buffer=           | ="*ladybird-console*"= | where console output goes                       |
| =ladybird-console-max-lines=        | 10000              | lines of console output kept                      |

=ladybird-track-hover= sets =track-mouse= and =mouse-fine-grained-tracking= while a page
buffer's window is selected and restores them afterwards.

The page has the size of the smallest window that shows its buffer.  It keeps that size
while the minibuffer or the echo area grows beyond one line and borrows lines from the
window.

* Testing

#+begin_src sh
make test                            # test-zig, test-native, test-elisp
make byte-compile checkdoc           # warnings are errors
make package-lint                    # installs package-lint under ~/.cache on first use
make test-mock                       # ERT against tools/mock-server.py, fake module
make test-mock-native                # the same with the native module
test/elate/run.sh                    # the mock matrix
test/elate/run-live.sh               # the live matrix; also make live
#+end_src

- The unit suites need nothing but Emacs, Zig and Python: =make test= runs the module's
  Zig tests, its tests in Emacs against stream fixtures, and the ERT tests of the package
  with a module written in Lisp.  =make test-mock= and =make test-mock-native= run the
  package against =tools/mock-server.py=.
- The mock matrix, =test/elate/run.sh=, drives the package in sandboxed Emacs sessions of
  [[https://github.com/dakra/elate][elate]] against the mock server over standard input and output, a Unix socket and TCP.
- The live matrix, =test/elate/run-live.sh=, does the same against a real Ladybird server
  with pages it serves itself: over standard input and output and over a Unix socket on
  this machine, and over ssh and an ssh-forwarded socket on another one.  It checks what
  the page reports about itself and the colours on the canvas.

The live matrix takes its servers from the environment:

| Variable                       | Meaning                                              |
|--------------------------------+------------------------------------------------------|
| =LADYBIRD_LIVE_PROGRAM=        | the local server; without it the local variants are skipped |
| =LADYBIRD_LIVE_SSH_HOST=       | ssh destination of a remote machine; without it the remote variants are skipped |
| =LADYBIRD_LIVE_REMOTE_PROGRAM= | the server on that machine                           |

[[file:test/elate/README.md][test/elate/README.md]] has the scenarios, the other variables and how the pages reach a
remote server.

- =lisp/ladybird-keys.el= translates Emacs events into the protocol's key and mouse fields.

  of the package run with it.
- =test/elate/= has the scenarios of the mock matrix and, under =live/=, those of the
  live matrix with their pages.
- =plans/= has the protocol and the design of each part.
