#+TITLE: ladybird — Ladybird pages in an Emacs canvas

=ladybird= shows web pages rendered by the [[https://ladybird.org][Ladybird]] browser in an Emacs buffer.  A Ladybird
server process renders the page and sends the changed pixels; a native module paints
them into an Emacs 32 canvas image; the mouse, the wheel and the keyboard go back to the
page.  The server can run on this machine or on another one, and with a socket its pages
outlive the Emacs that shows them.

=ladybird= is a working name.

* Status

The Emacs side is in this repository: the Lisp package, the native module, a mock server
and the tests.

The Ladybird side, a headless mode =Ladybird --headless=emacs= that speaks the protocol
of [[file:plans/01-protocol.md][plans/01-protocol.md]], is under development on a branch of Ladybird named
=emacs-headless= and is in no Ladybird release.

The two are run together by the live test matrix (see Testing): a macOS server on this
machine over standard input and output and over a Unix socket, with frames in shared
memory, and a Linux server in a virtual machine over ssh and over an ssh-forwarded
socket, with frames in the stream; the same server started by systemd socket activation
in a user session answers on the default socket.  The matrix runs at a device pixel
ratio of 1; a ratio of 2 is checked by hand on a Retina display.  A server across the
internet, reached as =/ssh:HOST:/PATH=, is checked by hand.  Not tested: TCP and Emacs on
Linux.

=tools/mock-server.py= stands in for the server in the tests: it draws a test gradient,
marks mouse presses and typed keys, draws hint labels, and answers the protocol's
commands with canned data.

A server started in the background on the default socket keeps its pages when Emacs
quits (see Hosts and transports).  The live matrix tries it on the macOS server on this
machine (=live-session=): an Emacs that starts the server, opens two pages and quits, the
next Emacs finding the server without configuration and getting both pages back with
their history and without loading them again, a detach, and attaching the pages one at
a time.

A server holds several pages, each in its own buffer (see Several pages): 16 by
default, or as many as =--emacs-max-views=N= says.  The live matrix tries them on the
macOS server on this machine and the Linux server in the virtual machine, over all four
connections (=live-pages=): two pages painting their own canvases, a cookie one sets and
the other reads, a page in no window sending no frames and a full frame once it is shown
again, where =ladybird-new-page-display= puts a new page, the limit, closing a page that
is animating, and the pages a socket server kept coming back with =ladybird-connect=.  A
server whose welcome names no number, or the number 1, holds one page: a command that
opens a second page on it loads the URL in the page there is and says so.

A page can open pages of its own (=window.open=, a link with a =target=, a middle click),
which get buffers in the background (see Several pages).  The live matrix tries them on
both servers over all four connections (=live-popups=): a link with =target=_blank=,
=window.open= with =window.opener=, a page closing its window or itself, the limit giving
a blocked popup, and a hinted click.

Not there yet: view source, uploads from this machine (the file picker returns paths on
the server's machine), downloads, bookmarks and profiles.

* Requirements

- Emacs 32 with canvas images and dynamic modules.
- The native module, built with Zig 0.17 (=make build=).
- A server: Ladybird built from its =emacs-headless= branch, or the mock server, which
  needs Python 3.11 or later.

* Building

#+begin_src sh
make build      # ladybird-module.dylib or .so next to the Makefile
make test       # Zig tests, module tests in Emacs, ERT tests of the package
#+end_src

Put =lisp/= on the =load-path=.  The module is looked for next to the Lisp files and in
the directory above them; =ladybird-module-directory= names another place.

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/ladybird/lisp")
(require 'ladybird)
#+end_src

* Quick start

With a Ladybird that has the headless mode:

#+begin_src emacs-lisp
(setq ladybird-program "/path/to/Ladybird")
;; M-x ladybird RET https://ladybird.org RET
#+end_src

The first =M-x ladybird= asks "No Ladybird server is running.  Start one?".  =y= starts
this machine's server in the background, on the default socket, and opens the page there;
=M-x ladybird-start-server= starts it without opening a page.  That server outlives
Emacs: quit Emacs, start it again, and =M-x ladybird-connect= gives every page it kept a
buffer again, =M-x ladybird-attach= only the page picked.  In a page buffer =C-c C-d=
detaches, killing the page buffers of the server and leaving their pages there, and
=M-x ladybird-attach= (=C-c C-a= in a page buffer) attaches them again; killing a page
buffer closes its page.  A server on another machine keeps its pages the same way, reached
through its socket over ssh (see [[*Other hosts]]).  =n= instead starts a
server for this Emacs alone, over standard input and output, whose pages end with Emacs.

With the mock server, which ends with its connection:

#+begin_src emacs-lisp
(setq ladybird-hosts
      '(("mock" :command ("python3" "-I" "/path/to/ladybird/tools/mock-server.py")))
      ladybird-default-host "mock")
;; M-x ladybird RET mock://start RET
#+end_src

To open links from other packages in ladybird:

#+begin_src emacs-lisp
(setq browse-url-browser-function #'ladybird-browse-url)
;; or only some of them
(add-to-list 'browse-url-handlers '("\\`https?://.*\\.internal/" . ladybird-browse-url))
#+end_src

=ladybird-browse-url= loads the URL in the page buffer used last, and opens a new one when
there is none.

=C-u C-c C-l= opens a URL in a new page buffer on the same server, and =C-c C-s= switches
between page buffers by title and URL.

* Hosts and transports

A server keeps its pages for as long as it runs.  One that listens on a socket keeps
running when its connection ends, by a detach, a lost connection, quitting Emacs or a
crash of Emacs, and the next connection to it gives its pages buffers again.  The usual
one is this machine's server on the default socket, started in the background; a server
on another machine is reached through its socket over ssh.  A server over standard input
and output, here or over ssh, lives as long as its connection, so its pages end with Emacs
or with the ssh session: the throwaway option.

** The local server

The local server is the one on the default socket when something accepts connections
there.  When nothing does and no connection to the local server is open, =M-x ladybird=,
=ladybird-browse-url=, =M-x ladybird-connect= and the =local= entry of a host prompt ask
"No Ladybird server is running.  Start one?".  Yes runs =M-x ladybird-start-server=,
which starts =ladybird-program= with =--emacs-default-socket --emacs-background= and waits
until the socket accepts connections; =C-g= stops only the waiting, and the echo area says
how the start ended.  When the server cannot start and none accepts connections there
afterwards, it fails with the last line the start wrote to standard error; with a server
listening there already it says so and starts none.  =ladybird-autostart-server= set to
=t= starts the server without asking; in batch Emacs =ask= counts as nil.  With it set to
nil, or with no for an answer, the local server runs over standard input and output (see
below).  Without =ladybird-program= or the native module nothing is asked or started.

A server on the default socket is found without configuration, with shared memory, and is
dialled again like any socket when its connection is lost.  Quit Emacs and it keeps
running with its pages; in the next Emacs =M-x ladybird-connect= or =M-x ladybird= gives
them buffers again, and =M-x ladybird-attach= gives one to the page picked.  It also keeps
running once its last page is closed, which the echo area says; it stops when it is
stopped where it runs, for example by ending its process, or with =C-c= in the terminal of
a server started there without =--emacs-background=.

=--emacs-background= starts the server in a session of its own, so it outlives Emacs and
the terminal it was started from.  The command returns once the socket accepts
connections, and fails with the reason on standard error when the server cannot start,
for example because one listens there already:

#+begin_src sh
Ladybird --headless=emacs --emacs-default-socket --emacs-background
#+end_src

The server logs to =ladybird-emacs-PID.log= in the directory of the default socket, PID
being its process id, and the message of =M-x ladybird-start-server= names the log
(", logging to FILE").  A server on another socket or over standard input and output logs
to =$XDG_RUNTIME_DIR/ladybird-emacs-PID.log=.  Where that file cannot be made, in either
directory, or without =XDG_RUNTIME_DIR= for a server not on the default socket, the log
is =/tmp/ladybird-emacs-PID-XXXXXX.log=, with a random XXXXXX.  =--emacs-log=PATH= names
another file.

The default socket is =$XDG_RUNTIME_DIR/ladybird-emacs.sock=, or
=$TMPDIR/ladybird-emacs-UID/ladybird-emacs.sock= when =XDG_RUNTIME_DIR= is unset, empty or
relative, UID being your user id; a =TMPDIR= that is unset, empty or relative counts as
=/tmp=.  =(ladybird-default-socket)= returns it.  With =--emacs-default-socket= the server
creates the directory =ladybird-emacs-UID= with mode 0700, and refuses to start, naming
the directory, when it is a symbolic link, not a directory, not yours, or open to your
group or others, or when its parent is owned by neither root nor you, or is writable by
its group or others without being sticky; =--emacs-socket= does not check the directory of
the path it names.  Access control lists are not checked.  Under =/tmp= another user can
create =/tmp/ladybird-emacs-UID= first, which makes =--emacs-default-socket= refuse to
start; an =XDG_RUNTIME_DIR= or =TMPDIR= naming a directory of your own avoids that.  A
socket that another user owns is ignored, and so is one in a =ladybird-emacs-UID=
directory that fails those checks.

*** Starting the server on demand

With systemd, the user units in =contrib/systemd= listen on the default socket and start
the server on the first connection to it, so =M-x ladybird= finds a server without asking.
=ExecStart= in =ladybird-emacs.service= runs =Ladybird= from =/usr/local/bin=, =/usr/bin=
or the like; when Ladybird is elsewhere, set its full path there before enabling the
socket:

#+begin_src sh
mkdir -p ~/.config/systemd/user
cp contrib/systemd/ladybird-emacs.socket contrib/systemd/ladybird-emacs.service ~/.config/systemd/user/
# Only when Ladybird is not in /usr/local/bin or /usr/bin:
sed -i 's|^ExecStart=Ladybird|ExecStart=/path/to/Ladybird|' ~/.config/systemd/user/ladybird-emacs.service
systemctl --user enable --now ladybird-emacs.socket
#+end_src

After editing the installed units by hand, run =systemctl --user daemon-reload=.
=systemctl --user edit ladybird-emacs.service= instead adds an override, in which an empty
=ExecStart== line has to come before the new one:

#+begin_src conf
[Service]
ExecStart=
ExecStart=/path/to/Ladybird --headless=emacs --emacs-socket-activation
#+end_src

With a wrong =ExecStart= a connection to the socket waits for a server that never
answers, and after a few tries systemd gives up and the socket unit fails; =systemctl --user status ladybird-emacs.service= and
=journalctl --user -u ladybird-emacs= say why.

The socket is =%t/ladybird-emacs.sock=, that is =$XDG_RUNTIME_DIR/ladybird-emacs.sock=,
so Emacs has to see the same =XDG_RUNTIME_DIR= as the user's systemd.  Anything that looks
for the local server connects to the default socket and so starts the server, for example
the host prompt of =ladybird-default-host= set to =ask=.  The server, started with
=--emacs-socket-activation=, serves the socket systemd hands it, says in the journal where
it logs, and logs to =$XDG_RUNTIME_DIR/ladybird-emacs-PID.log= without =--emacs-log=.
=systemctl --user stop ladybird-emacs.service= ends the server and its pages, and the next
connection starts a new one; stop =ladybird-emacs.socket= as well to have none, which also
removes the socket file.

On macOS =--emacs-socket-activation= takes the socket named =Listeners= in the =Sockets=
of the server's launchd job, but no LaunchAgent comes with the package: a LaunchAgent
cannot name the default socket in =$TMPDIR=.

** Detach and attach

=C-c C-d= (=ladybird-detach=, =d= in command mode) detaches from the current buffer's
server: it kills the server's page buffers without closing their pages and closes the
connection, which is not dialled again; with more than one buffer it asks first.  With
=C-u= it kills only the current buffer: its page stays open on the server, hidden, also
when the connection is dialled again, until =C-c C-s=, =C-c C-a= or
=M-x ladybird-connect= gives it a buffer again.  =C-u= in the connection's last page
buffer detaches the whole connection.  Detaching from a server over standard input and
output is refused, since its pages end with the connection, and so is detaching a
connection that is down while pages whose buffers were killed meanwhile wait to be closed:
once it is back they are.

Killing a page buffer closes its page; with =ladybird-keep-view-on-kill= set it leaves the
page open as =C-u C-c C-d= does.

=C-c C-a= (=ladybird-attach=, =a= in command mode) reads one of the server's pages that
have no buffer in this Emacs, by any part of its title or URL, and gives only that one a
buffer; with more than one such page the last entry, =All N pages=, gives them all one.
The buffer appears as =ladybird-new-page-display= says, of several the first.  The server
is the one of the current page buffer, else the one =M-x ladybird= opens on, and with
=C-u= it is read.  Without a connection to it =ladybird-attach= connects first, gives no
page a buffer, hides them all and then reads one; the pages not picked stay open on the
server, hidden and without a buffer.  A connection left without a page buffer, after
=C-g= or with nothing to attach, closes again unless it had page buffers before.  It
starts no server and dials only a host's socket endpoints: with nothing on the default
socket, a host without a socket endpoint that is not connected, or a socket nothing
listens on, it says "No server on ...", and for a socket reached by ssh "cannot reach ...".
A server whose pages all have buffers, or one without pages, is only reported.

=M-x ladybird-connect= reads a host and connects without opening a page.  It gives every
page the server has open a buffer, also on a connection that is open already, and shows
one of them: the page buffer used last if it is one, else the first; the echo area says
how many there are.

** Other hosts

Other servers are named in =ladybird-hosts=, an alist of a label and one or more
endpoints, tried in order:

| Endpoint                               | Connection                                     |
|----------------------------------------+------------------------------------------------|
| ="local"=                              | =ladybird-program= as a local process            |
| ="ssh:HOST"=, ="ssh://USER@HOST:PORT"= | =ladybird-program= on HOST, run by =ssh -T=      |
| ="/PATH"=, ="unix:///PATH"=            | a Unix socket                                  |
| ="/ssh:HOST:/PATH"=                    | a Unix socket on HOST, through =ssh -W=          |
| ="/ssh:USER@HOST#PORT:/PATH"=          | the same with a user, a port or both           |
| ="tcp://HOST:PORT"=                    | a TCP port, unauthenticated                    |
| ="tls://HOST:PORT"=                    | a TCP port with TLS                            |
| =(:ssh HOST :program P :args LIST)=    | ssh with another program or arguments          |
| =(:command (PROGRAM ARG...))=          | that command as a local process                |
| =(:kind unix :path PATH :shm nil)=     | a Unix socket, without shared memory           |

#+begin_src emacs-lisp
(setq ladybird-hosts '(("devbox" . "/ssh:devbox:/run/user/1000/ladybird-emacs.sock")
                     ("work" "/tmp/work.sock"
                      "/ssh:work:/run/user/1000/ladybird-emacs.sock")
                     ("scratch" :ssh "devbox" :program "/opt/ladybird/bin/Ladybird")))
#+end_src

The Ladybird server does not listen on TCP; =tcp://= and =tls://= need something in front
of its socket, and whoever reaches that port controls the browser.

=M-x ladybird= opens on =ladybird-default-host=: the local server, a label, or =ask=, and
without a local server the first host.  With a prefix argument it asks.  A host of
=ladybird-hosts=, picked by its label or by =ladybird-default-host=, is used as it is: it
is neither started nor replaced by a local server, and one that cannot be reached is an
error.

For pages that outlive Emacs on another machine, run the server there on a socket, with
the systemd units above or in the background:

#+begin_src sh
# on devbox, or as ssh devbox Ladybird ... from here
Ladybird --headless=emacs --emacs-socket=/run/user/1000/ladybird-emacs.sock --emacs-background
#+end_src

and name the socket as a remote file, =/ssh:devbox:/run/user/1000/ladybird-emacs.sock=.
PATH is absolute and taken literally; HOST can be an alias of =~/.ssh/config=, which an IPv6
address needs, and a host of a tailnet is one like any other as long as it runs sshd.  ssh
has no terminal here: a password or passphrase it needs is asked for by askpass, again on
every redial.  The server's sshd must allow stream forwarding.  A
connection that is lost is dialled again as for any socket.

A socket that =ssh -L= forwards works too:

#+begin_src sh
ssh -N -o StreamLocalBindUnlink=yes -L /tmp/devbox.sock:/run/user/1000/ladybird-emacs.sock devbox
#+end_src

With systemd-logind, =/run/user/1000= is removed with the last session of the user, and
the socket in it with it: started by a one-off =ssh devbox ...=, the server keeps running
but cannot be reached once that session ends.  =loginctl enable-linger= keeps the
directory; a socket outside it does not depend on it.

#+begin_src emacs-lisp
(setq ladybird-hosts '(("devbox" . "/tmp/devbox.sock")))
;; or, saying that the socket is forwarded:
(setq ladybird-hosts '(("devbox" :kind unix :path "/tmp/devbox.sock" :shm nil)))
#+end_src

With =ControlMaster auto= in =~/.ssh/config=, =ssh -N -L= hands the forwarding to the
shared connection and returns at once.  Either give the forwarding a connection of its
own with =-o ControlMaster=no -o ControlPath=none=, or end it with =ssh -O exit devbox=.

Local servers hand frames over in shared memory, one segment per page.  Over a forwarded
socket the segment cannot be opened here; the server is told and sends the pixels in the
stream, compressed with zstd.  That costs the first frame of the first connection; the
endpoint is remembered for the rest of the Emacs session and not offered shared memory
again.  =:shm nil= in the endpoint says it up front.  The module maps a segment at the
size it has then and trusts the server not to shrink it: reading from pages that are gone
would kill Emacs.  Only a server on this machine can hand over a segment, and one run by
the same user can harm Emacs in other ways already; for a Unix socket of a server that is
not, say so with =:shm nil= in its endpoint.

A server reached through a Unix socket counts as being on this machine when its endpoint
does not say =:shm nil=, its segments could be mapped and it names this machine as its
host.  For any other server, file names are asked for as paths on the server's machine.

** Servers over standard input and output

The =local=, =ssh:HOST= and =(:ssh HOST ...)= endpoints, =:command= and the local server with
=ladybird-autostart-server= nil or a no for an answer run the server over its standard
input and output: =PROGRAM --headless=emacs= here or on the ssh host.  For the local
server the echo area says once for that connection that its pages end with Emacs.

To try a server on another machine without setting anything up there, name its program,
which ssh starts and which ends with the connection:

#+begin_src emacs-lisp
(setq ladybird-hosts
      '(("scratch" :ssh "devbox" :program "/opt/ladybird/bin/Ladybird")))
#+end_src

Without =:program= it is =ladybird-program= that runs on the other machine, and without
=:args= it gets =ladybird-program-arguments=; a =ladybird-program= that is a path on this
machine seldom exists there.

While a connection to the local server over a socket is open or being dialled again, new
pages go to that server, wherever it was found.  A server on the default socket comes
before one over standard input and output: once one listens there, for example after
=M-x ladybird-start-server=, the pages that =M-x ladybird= and =ladybird-browse-url= open
go to it, and =ladybird-connect= shows its pages.  The pages open on the server over
standard input and output stay there until they are closed, which the message of
=ladybird-start-server= says, and so do the pages opened from them: a new page from one
of its buffers, a link followed in a new buffer, a blocked popup opened and the windows
the page opens.

** Lost connections

A connection that is lost is dialled again after 1, 2, 4 and up to 30 seconds while it
has page buffers (=ladybird-reconnect=); the header line says so.  The buffers keep their
last frame and re-attach to their pages; a page the server no longer has is opened again
with its URL, and so is every page when another server process answers.  A page that had
no buffer stays without one, hidden; a page the server opened meanwhile gets one.  A page
whose buffer was killed meanwhile is closed once the connection is back.  A question of a
page that is open when the connection is lost stays open until it is back, then closes
and is asked again if the page still waits for it; an answer given meanwhile is lost.
The delays start at one second again after a connection has lasted ten seconds.  A
server over standard input and output that exited by itself is reported with its exit
status and started again only with =ladybird-reconnect= set to =always=.  When another
client takes the server over the buffers show =[taken over]=, and
=M-x ladybird-reconnect= takes it back.

A server is pinged after =ladybird-keepalive-interval= seconds of silence and its
connection dropped when no answer comes within =ladybird-ping-timeout=.

When a local or ssh server cannot be started or exits, the message has the last line it
or ssh wrote to standard error; the buffer =" *ladybird-stderr*"= has all of it.

* Several pages

Every page is a buffer of its own.  =M-x ladybird=, =C-u C-c C-l=, =c= in command mode,
=C-u C-c C-o= on a link, "Open Link in New Buffer" and =ladybird-open-blocked-popup= open a
new page on the server of the current one (=M-x ladybird= on =ladybird-default-host=), with
a view of its own on that server; the pages of a server share its cookies and storage.
=ladybird-new-page-display= says where the new buffer appears: in the selected window
(the default), in another window, or nowhere (=background=).  The buffer goes through
=display-buffer=, so a rule of =display-buffer-alist= for =*ladybird:= buffers comes first.

A server holds as many pages as its welcome's =max_views=: the Ladybird server 16, or N
with =--emacs-max-views=N= (=ladybird-program-arguments= for a server the package starts).
Once it has that many, a further page is refused with a message saying so, before the
server is asked; the message counts the pages there without a buffer here (see
[[*Detach and attach]]).  =C-c C-s=, =C-c C-a= and =M-x ladybird-connect= give those pages
buffers again, with their current titles and URLs.  A server whose welcome names no
number, or the number 1, holds one page, and a further page loads the URL in it.

A page that a page opens, after a click or key of the user in it, gets a buffer of its
own on the same server, and the echo area names the page that opened it and says that
=C-c C-s= gets there.  It appears in no window, so a page that opens one on every click
takes no window and no focus; it is told it is hidden and renders nothing until a window
shows it.  =C-c C-s= annotates it with the page that opened it.  A page that closes its
window takes its buffer along: a window made for it is deleted and any other shows the
buffer it showed before (=quit-restore-window=); the selected window stays selected.  The
buffer goes through =display-buffer= with the category =ladybird-popup=, so a rule of
=display-buffer-alist= can show it, without selecting its window:

#+begin_src emacs-lisp
(add-to-list 'display-buffer-alist
             '((category . ladybird-popup) (display-buffer-pop-up-window)))
#+end_src

When the server makes no view for the page, the echo area says the popup was blocked and
what =ladybird-open-blocked-popup= does with its URL: open it as a new page, load it in the
page there is on a server that holds one page, or nothing while a server holds all the
pages it can.

A page in no window is told it is hidden, and its server sends it no frames until a
window shows it again; then it repaints in full.  Iconifying a frame or showing it
again counts as hiding or showing its pages.  After a reconnect the pages that were
shown before send a whole frame at once, the others when a window shows them; every page
is told whether a window shows it as soon as the reconnecting command has shown its
page.  =C-c C-s=
(=ladybird-switch-to-page=) reads a page by any part of its title or URL, from every
server; with several servers each is annotated with its host.

There is no tab strip of its own.  Emacs's tab-line shows the page buffers of a window as
tabs:

#+begin_src emacs-lisp
(add-hook 'ladybird-mode-hook #'tab-line-mode)
(setq tab-line-tabs-function #'tab-line-tabs-mode-buffers)
#+end_src

With tab-bar, one tab per page: a page shown in a tab already selects that tab, any
other gets a new one.

#+begin_src emacs-lisp
(add-to-list 'display-buffer-alist
             '("\\`\\*ladybird: " (display-buffer-in-tab)
               (reusable-frames . t)))
#+end_src

That rule also takes the pages that pages open, and selects their tabs.  A rule for
their category that comes first keeps them in the background:

#+begin_src emacs-lisp
(add-to-list 'display-buffer-alist
             '((category . ladybird-popup) (display-buffer-no-window)
               (allow-no-window . t)))
#+end_src

* Keys

A new page buffer starts in =ladybird-command-mode=, where single keys are commands
(below): =n= and =p= scroll, =g= opens a URL, =o= follows a link.  =i= switches to page
mode, and so does a text field of the page that gets the focus, whether by a click, =TAB=,
=o=, a script or autofocus; command mode comes back when no field has the focus.
Command mode switched on by hand while a field has the focus stays; page mode switched on
there also ends when no field has the focus.  =ladybird-initial-mode= set to =page=
starts buffers in page mode instead.

The switching is done by =ladybird-follow-field-focus=, the default of the hook
=ladybird-field-focus-functions=.  Each function in it is called with FOCUSED and
ACTIVATION when the focus moves into or out of the page's text fields.  ACTIVATION is nil
for a focus the page moved without user input, such as autofocus, and also when a key
moves the focus into a frame of another site; such a field calls the functions again with
ACTIVATION when the user first clicks or types in the page.  To stay in command mode until
a click in the field or =i=:

#+begin_src emacs-lisp
(defun my-ladybird-field-focus (focused activation)
  (when (or activation (not focused))
    (ladybird-follow-field-focus focused)))
(setopt ladybird-field-focus-functions '(my-ladybird-field-focus))
#+end_src

In page mode keys go to the page, as in a terminal emulator: what inserts itself, =RET=,
=TAB=, =DEL=, =S-SPC=, the cursor and function keys with any modifiers, and =<escape>= in a
graphical frame.  The Emacs editing and motion keys of =ladybird-translated-keys= are
translated to what does the same in a browser on the server's platform (table below).  The
mouse and the wheel always act on the page.  Everything else keeps its Emacs meaning, in
particular =C-x=, =C-c=, =C-h=, =M-x=, =M-:=, =C-u= and =C-g=, and the keys of
=ladybird-emacs-keys=: =<f1>= (help), =<f3>= and =<f4>= (keyboard macros), =<f10>= (the
menu bar) and =<f11>= (full screen).  A key in that option stays with Emacs also when it
is in =ladybird-translated-keys=.  A numeric prefix argument repeats a key (=C-u 3 a=
types three), and a keyboard macro recorded with =<f3>= and =<f4>= replays its keys into
the page.  With an input method the characters it produces are sent.

With evil or meow the keymaps of their states take keys before =ladybird-mode= sees them;
for keys to go to the page, start page buffers in Emacs state, for example with
=(evil-set-initial-state 'ladybird-mode 'emacs)=.

behind it is that key with Meta.  A mouse or wheel event after =C-c C-q= is handled as
usual.

At the end of a line =C-k= removes the line break.  =C-M-_= and =C-S-z= (redo) are
translated too once they are added to the option; other keys added to it are sent as
they are.  A key taken out of it keeps its Emacs meaning.  Both columns were tried
against Ladybird servers on macOS and on Linux.

=C-s= reads the search string in the minibuffer.  The page shows the matches while the
string is typed and the minibuffer shows their number; =C-s= and =C-r= move to the next
and the previous match, =RET= leaves the matches highlighted, =C-g= ends the search.
Ladybird turns the match the search ended on into the page's selection.

=C-c C-o= (=o= in command mode) follows a link from the keyboard.  The page puts a label
made of the characters of =ladybird-hint-alphabet= on every link, button and field in the
window, and typing a label activates its element: a link or a button is clicked, a field
gets the focus and command mode is left, so that typing goes into it.  Each character
narrows the labels the page shows; the echo area shows what has been typed, how many
labels are left and, for the last one, its text or URL.  A character that continues no
label is refused with a beep, =DEL= takes the last one back, and =C-g= or =<escape>= (in
a graphical frame; in a terminal =ESC= starts a Meta key) ends without a choice.  Any
other key, a click or the wheel ends the hints too and then does what it does otherwise;
moving the mouse does not.  With =C-u C-c C-o= a link opens in a new buffer, if it is an
http or https URL, or a file URL on a page that is a file itself; another one is refused
with a message.  Characters typed before the labels arrive count.  When the page ends the
hints (it navigates, crashes or does not answer in time) or the server refuses them, they
end here too, with a message.  It needs a server whose welcome lists the =hints= feature.

What a page asks comes to the minibuffer: alerts (in the echo area; =ladybird-alert-style=
makes them wait for a key), confirmations, prompts, the choices of a select element,
files, colours, dates, permissions and URLs for other programs.  =C-g= declines, and so
does any other way out of the prompt.  While the minibuffer is in use a question waits
for it.  A question the server withdraws closes by itself, and so do the questions of a
connection that is detached, closed with its last page buffer or taken over by another
client, without an answer: a server on a socket asks them again when a client connects.
One of them open around another question, or around the minibuffer of a command run in it,
closes once that one ends; neither its answer nor its decline is sent.

A permission and a URL for another program are answered with a word typed or completed in
full (=allow once=, =allow always=, =deny=; =open on server=, =open here=, =deny=), and
keys typed before the question appeared are discarded.  =RET= on a part of a choice, or on
any other text, asks again with the input gone, so keys meant for the page do not answer
it; =RET= on nothing declines.  =open here= hands the URL to
=browse-url-secondary-browser-function= and is offered for http, https and mailto URLs
only.

A right click pops up a menu for the link, image, selection or text field under the
pointer.  Its "Open Link" and "Open Link in New Buffer" load the same URLs as
=C-u C-c C-o=.

The header line shows the page's URL first, at least its scheme and host, then the
title in the room that is left.

* Display resolution

=ladybird-device-pixel-ratio= is the number of device pixels the server renders per Emacs
pixel.

On macOS it is 1.0 by default: the page is rendered at one pixel per point and Emacs
scales the canvas up on a Retina display, so text is less sharp than in the rest of the
frame.  The NS port of Emacs draws a canvas without its image transform (=:scale=), so a
page rendered at the display's resolution would show only its top left part.

With =ladybird-device-pixel-ratio= set to nil the ratio is the frame's scale factor
(=frame-scale-factor=) and the canvas is shown scaled down by it, one canvas pixel per
device pixel.  On macOS that needs an Emacs built with
=plans/emacs-canvas-ns-transform.patch=, which makes the NS port keep the transform.
For Homebrew's emacs-plus the patch is registered in =~/.config/emacs-plus/build.yml=
under the name =canvas-ns-transform=.

Elsewhere the default is nil.

* Testing

#+begin_src sh
make test                            # test-zig, test-native, test-elisp
make byte-compile checkdoc           # warnings are errors
make package-lint                    # installs package-lint under ~/.cache on first use
make test-mock                       # ERT against tools/mock-server.py, fake module
make test-mock-native                # the same with the native module
test/elate/run.sh                    # the mock matrix
test/elate/run-live.sh               # the live matrix; also make live
#+end_src

- The unit suites need nothing but Emacs, Zig and Python: =make test= runs the module's
  Zig tests, its tests in Emacs against stream fixtures, and the ERT tests of the package
  with a module written in Lisp.  =make test-mock= and =make test-mock-native= run the
  package against =tools/mock-server.py=.
- The mock matrix, =test/elate/run.sh=, drives the package in sandboxed Emacs sessions of
  [[https://github.com/dakra/elate][elate]] against the mock server over standard input and output, a Unix socket and TCP,
  and on the default socket, started in the background.
- The live matrix, =test/elate/run-live.sh=, does the same against a real Ladybird server
  with pages it serves itself: over standard input and output and over a Unix socket on
  this machine, and over ssh and an ssh-forwarded socket on another one; a server it
  starts in the background on the default socket, here and on the other machine.  It
  checks what the page reports about itself and the colours on the canvas.

The live matrix takes its servers from the environment:

| Variable                       | Meaning                                              |
|--------------------------------+------------------------------------------------------|
| =LADYBIRD_LIVE_PROGRAM=        | the local server; without it the local variants are skipped |
| =LADYBIRD_LIVE_SSH_HOST=       | ssh destination of a remote machine; without it the remote variants are skipped |
| =LADYBIRD_LIVE_REMOTE_PROGRAM= | the server on that machine                           |

[[file:test/elate/README.md][test/elate/README.md]] has the scenarios, the other variables and how the pages reach a
remote server.
